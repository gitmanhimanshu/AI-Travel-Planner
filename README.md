# ✈️ AI Travel Planner

A full-stack web application that turns a short travel brief into a complete,
day-by-day itinerary with real activities, restaurants, transport options and an
honest budget breakdown — generated by an LLM and rendered in a modern,
responsive UI.

Built with **Flask + SQLAlchemy** on the server and **vanilla JavaScript +
Bootstrap 5** in the browser. No frontend framework, no build step: clone, install,
run.

---

## 🚀 Quick start

**Windows (PowerShell)**

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
python run.py
```

**macOS / Linux**

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python run.py
```

Open **<http://127.0.0.1:5000>** — that's it. The database creates itself on
first run.

### Turning on the real AI

The app runs straight away in **demo mode** (an orange banner says so) using a
built-in sample generator, so you can click through every page without a key.
For real AI itineraries:

1. Get a **free** Gemini key at <https://aistudio.google.com/apikey> (starts with `AIza`).
2. Open `.env` and set it:
   ```
   AI_API_KEY=AIza...your-key-here...
   ```
3. Restart `python run.py`. The banner disappears.

Check that the key works before planning a trip:

```bash
python check_ai.py
```

> **You only need that one key.** Weather already works without any key
> (Open-Meteo) — leave `WEATHER_API_KEY` empty.

Stuck? See [Troubleshooting](#troubleshooting).

## Overview

The user fills in one form — destination, starting city, dates, travellers,
budget, travel style, interests, transport and stay preferences, plus any free-text
requirements. The backend turns that into a structured prompt, asks the model for a
**schema-constrained JSON itinerary**, validates and normalises the response, saves
it (if the user is signed in) and returns it to the browser, which renders a
timeline, a budget dashboard, a weather panel and a map-linked list of places.

Nothing reloads the page: every interaction goes through `fetch()` against a JSON
API.

**It runs without an API key.** With `AI_API_KEY` unset the app falls back to a
built-in demo generator so every screen, route and interaction is explorable
immediately. Add a key and the same code paths call the real model.

## Features

### Planning
- One-page planner form with live duration calculation and client-side validation
- Multi-select travel styles and interests, budget levels plus an optional exact amount
- Day-by-day itinerary: morning / afternoon / evening, with times, descriptions and per-item costs
- Per-day and per-category cost estimates, compared against the budget the user entered

### AI
- **AI Trip Planner** — the full itinerary, constrained to a JSON schema
- **AI Budget Optimiser** — concrete swaps that bring an over-budget plan back down
- **AI Travel Assistant** — a chat panel that knows the current itinerary
- **AI Packing Assistant** — a list built from destination, season, length and activities
- **AI Travel Tips** — destination-specific advice returned with every plan

### Around the trip
- Live weather (current conditions + 7-day forecast), key-less by default
- "View on map" links for every place, with no map API dependency
- Explore page with 12 curated destinations, search and tag filters; "Plan Trip" prefills the form
- Accounts, saved trips, favourites and delete-with-confirmation

### Interface
- Responsive from 320 px up, custom-themed Bootstrap 5 (not a stock template)
- Toasts, spinners, skeleton loaders, empty states, error states
- A staged loading sequence while the AI works ("✨ AI is planning your perfect trip...")
- Print-friendly itinerary stylesheet

## Architecture

```
Browser (Bootstrap 5 + vanilla JS)
  |
  |  fetch() JSON + X-CSRF-Token, same-origin cookies
  v
Flask blueprints  ── pages.py  (HTML shells)
                  ── auth.py   (/api/auth/*)
                  ── trips.py  (/api/trips/*)
                  ── ai.py     (/api/ai/*)
                  ── destinations.py (/api/destinations, /api/weather)
  |
  v
Service layer
  ── ai_provider.py       provider abstraction (Gemini | Claude | mock), error translation
  ── ai_service.py        prompts + JSON schemas + use cases
  ── itinerary_service.py validation / normalisation / budget maths
  ── weather_service.py   Open-Meteo or OpenWeatherMap, never fatal
  ── destinations_data.py static catalogue
  |
  v
SQLAlchemy models  ── User ──< Trip ──< Favorite
  |
  v
SQLite (dev) / PostgreSQL (prod)
```

Three rules keep this maintainable:

1. **Routes do not talk to the AI.** They validate input, call a service, shape a response.
2. **Services do not touch Flask request state.** They take plain dicts and return plain dicts.
3. **The frontend never sees a raw model response.** Everything passes through `itinerary_service.normalize_itinerary()` first, so every key the UI renders is guaranteed to exist.

## Environment setup

Open `.env` and fill in what you need. Every value has a working default except
the AI key.

| Variable | Required | What it does |
|---|---|---|
| `SECRET_KEY` | Recommended | Signs the session cookie. Use a long random string in production. |
| `AI_API_KEY` | For real AI | Your Gemini (or Claude) key. Leave empty to run in demo mode. |
| `AI_PROVIDER` | No | `auto` (default — detects from the key prefix), `gemini`, `claude`, or `mock`. |
| `AI_MODEL` | No | Empty = provider default (`gemini-2.5-flash` / `claude-opus-5`). |
| `AI_TEMPERATURE` | No | Gemini only. `0.8` default — lower is more predictable. |
| `AI_EFFORT`, `AI_MAX_TOKENS` | No | Claude only. Thinking depth and output ceiling. |
| `DATABASE_URL` | No | Empty = SQLite at `instance/travel.db`. |
| `WEATHER_API_KEY` | No | Empty = key-less Open-Meteo. Set it to use OpenWeatherMap. |
| `SESSION_COOKIE_SECURE` | Prod | `true` when serving over HTTPS. |
| `FLASK_ENV` | No | `development` (default) or `production`. |

The app reads the key **server-side only** — it never reaches the browser.

Generate a secret key:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

### Getting a free Gemini key

1. Open <https://aistudio.google.com/apikey> and sign in with a Google account.
2. Click **Create API key** and copy it (it starts with `AIza`).
3. Paste it into `.env` as `AI_API_KEY=AIza...` and restart the app.

`AI_PROVIDER=auto` recognises the `AIza` prefix and switches to Gemini on its
own — no other change needed. Verify it with:

```bash
python check_ai.py
```

That prints the detected provider, lists the models your key can call and sends
one small test request. If a model name ever stops working, copy a working one
from that list into `AI_MODEL`.

**Free tier limits** apply per minute and per day, and they change over time.
When you hit one the app says *"Gemini's free-tier rate limit was reached"* —
wait a minute and retry. `gemini-2.5-flash-lite` has a more generous quota if
you plan a lot of trips.

To use Claude instead: `pip install anthropic`, put an `sk-ant-...` key in
`AI_API_KEY`, and auto-detection handles the rest.

## Database setup

Nothing to run. On startup the app creates `instance/travel.db` and every table
via `db.create_all()`.

**To reset the database**, delete the file and restart:

```powershell
Remove-Item instance\travel.db      # Windows
```
```bash
rm instance/travel.db               # macOS / Linux
```

**To use PostgreSQL in production**, install the driver and point `DATABASE_URL`
at your server — no code changes:

```bash
pip install "psycopg[binary]"
```
```
DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/travel
```

For a real deployment, add Alembic (`pip install alembic`) so schema changes are
migrations rather than `create_all()`.

## API documentation

All endpoints speak JSON. Successful responses include `"success": true`; failures
return `{"success": false, "error": "<human-readable message>"}` with a matching
HTTP status.

State-changing requests (`POST`, `DELETE`) require the header
`X-CSRF-Token`, whose value is in the page's `<meta name="csrf-token">` tag.

### Auth

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| `POST` | `/api/auth/register` | – | Create an account and sign in. `{name, email, password}` |
| `POST` | `/api/auth/login` | – | Sign in. `{email, password}` |
| `POST` | `/api/auth/logout` | – | Clear the session |
| `GET` | `/api/auth/me` | – | Current user or `null`, plus a fresh CSRF token |

### Trips

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| `POST` | `/api/trips/generate` | Optional | Generate an itinerary; saves it when signed in |
| `GET` | `/api/trips` | Required | List the current user's trips |
| `GET` | `/api/trips/<id>` | Required | One trip with its full itinerary |
| `DELETE` | `/api/trips/<id>` | Required | Delete a trip |
| `POST` | `/api/trips/<id>/favorite` | Required | Toggle favourite |

### AI

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| `POST` | `/api/ai/chat` | Optional | Assistant reply. `{message, history[], trip_id?}` |
| `POST` | `/api/ai/packing-list` | Optional | Tailored packing list |
| `POST` | `/api/ai/optimize-budget` | Optional | Cheaper alternatives. `{target_budget, ...}` |

### Reference data

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| `GET` | `/api/destinations` | – | The curated destination catalogue |
| `GET` | `/api/destinations/<slug>` | – | One destination |
| `GET` | `/api/weather/<destination>` | – | Current weather + 7-day forecast |

### Status codes

| Code | Meaning |
|---|---|
| `200` / `201` | Success |
| `401` | Not signed in |
| `403` | Missing or stale CSRF token |
| `404` | Not found, or not owned by the current user |
| `422` | Validation failed |
| `502` | The AI service failed or returned something unusable |
| `500` | Unexpected server error (never leaks a stack trace) |

## How it all fits together

### How the frontend talks to Flask

Every page is a thin Jinja shell. `main.js` exposes one helper, `App.api()`, which
wraps `fetch()` with the JSON headers, the same-origin cookie, the CSRF token and
a single error type. Page scripts (`planner.js`, `itinerary.js`, `chat.js`,
`trips.js`, `explore.js`, `auth.js`) call it and render the result. Nothing
navigates except deliberate page changes.

A generated itinerary is stashed in `sessionStorage` so an anonymous user can move
from `/planner` to `/itinerary` without an account; signed-in users get
`?trip=<id>` and the server copy instead.

### How the AI integration works

1. `trips.py` validates the form into a clean dict (unknown styles and interests are dropped).
2. `ai_service.build_itinerary_prompt()` renders that dict into an explicit prompt, next to a system prompt that encodes the planning rules — budget, pacing, no two far-apart places in one day, honest costs.
3. The configured provider makes the call:
   - **Gemini** (`GeminiProvider`) — `response_mime_type: "application/json"` plus the itinerary **JSON schema** in `response_schema`, so valid JSON is guaranteed rather than requested. Gemini accepts a subset of JSON Schema, so `_to_gemini_schema()` strips `additionalProperties` first; if the schema is rejected anyway, the call retries in plain JSON mode with the schema described in the prompt.
   - **Claude** (`ClaudeProvider`) — `output_config.format` with the same schema, adaptive thinking, streaming, and server-side fallbacks.
4. `itinerary_service.normalize_itinerary()` coerces types, numbers every day, attaches real dates, recomputes the budget from its parts and fills any gaps. A short response is padded with a flagged placeholder day rather than breaking the page.
5. Only then does the itinerary reach a route.

Every SDK exception is translated into a sentence a user can act on — never a stack trace.

### Swapping the AI provider

`ai_provider.py` is the only file that knows a vendor exists — it ships with
three implementations (`GeminiProvider`, `ClaudeProvider`, `MockProvider`) behind
one two-method interface:

```python
complete_json(system, prompt, schema, context) -> dict
complete_text(system, messages, context)       -> str
```

Adding a fourth vendor means writing one class and registering it in
`get_provider()`. Prompts, routes, templates and JavaScript stay untouched —
which is exactly how Gemini support was added without editing anything else.

### How the database works

`User ──< Trip ──< Favorite`, all through SQLAlchemy relationships with cascading
deletes. The itinerary is stored as JSON text in `Trip.itinerary_json`, exposed
through a `trip.itinerary` property that encodes and decodes it — flexible enough
for a changing AI schema, while the columns you actually query (destination,
dates, budget) stay properly typed and indexed.

## Security notes

- Passwords are hashed with Werkzeug (PBKDF2); plaintext is never stored or logged.
- API keys live in environment variables, are read server-side only, and never reach the browser.
- Every state-changing API call is CSRF-checked against a session token compared in constant time.
- All queries go through SQLAlchemy's parameter binding — no string-built SQL.
- Trip routes filter by `user_id`, so one account cannot read or delete another's trips.
- Login failures return one message for both "no such user" and "wrong password" so the endpoint cannot enumerate accounts.
- Session cookies are `HttpOnly` + `SameSite=Lax`, and `Secure` in production.
- All AI and user text is rendered through `App.escapeHtml()`, never `innerHTML` with raw input.
- Unhandled exceptions return a generic message; details go to the server log only.
- HTTP client debug logging (which would echo prompts) is off unless `VERBOSE_HTTP_LOGS=true`.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Orange "Demo mode" banner | Expected without a key. Set `AI_API_KEY` in `.env` and restart. |
| "The Gemini API key is invalid" | Run `python check_ai.py`. Check the key and that `.env` sits next to `config.py`. |
| "Gemini's free-tier rate limit was reached" | Free-tier quota per minute/day. Wait, or switch `AI_MODEL` to `gemini-2.5-flash-lite`. |
| "The model '...' is not available for this key" | Run `python check_ai.py` and copy a listed model into `AI_MODEL`. |
| "Could not tell which AI service that key belongs to" | The key has an unusual prefix — set `AI_PROVIDER=gemini` explicitly. |
| `ModuleNotFoundError: google` | `pip install google-genai` |
| "Your session expired" on submit | Refresh the page to pick up a new CSRF token. |
| Weather card missing | The lookup failed or the place was not found; the app carries on by design. |
| `ModuleNotFoundError: flask_sqlalchemy` | The virtualenv is not active, or `pip install -r requirements.txt` did not run. |
| Port 5000 in use | `PORT=5001 python run.py` |
| Stale schema after a model change | Delete `instance/travel.db` and restart (dev only). |
